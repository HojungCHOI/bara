# 스케치 노트

사용자가 떠오르는 생각을 흘려보내지 않고 모아 두기 위한 규칙이다.

## 언제 쓰는가

사용자 입력이 다음 형식으로 시작할 때:

- `스케치 - 내용`
- `스케치- 내용` / `스케치 -내용` / `스케치 내용`
- `sketch - 내용`

## 무엇을 하는가

1. 저장소 루트의 `sketch.md`를 연다. 없으면 아래 "파일 서식"대로 새로 만든다.
2. 파일 **맨 아래에** 새 항목을 덧붙인다. 기존 내용은 절대 고치거나 지우지 않는다.
3. 한 항목은 네 부분으로 이루어진다.
   - **스케치** — 사용자가 쓴 원문을 한 글자도 바꾸지 않고 인용한다.
   - **의도** — 사용자가 이 메모로 무엇을 하려는지 추론한다. 확실하지 않으면 확실하지 않다고 쓴다.
   - **내용** — 메모를 실제 할 일이나 개념으로 풀어 정리한다.
   - **내 생각** — 판단을 보탠다. 기술적 걸림돌, 더 나은 대안, 먼저 정해야 할 것, 기존 계획과 충돌하는 지점.
4. 기록한 뒤 사용자에게는 **짧게** 확인만 한다. 항목 전문을 다시 읊지 않는다.

## 파일 서식

파일이 없으면 이 머리말로 시작한다.

```markdown
# 스케치

떠오른 생각을 그때그때 모아 두는 곳. 각 항목은 원문과 그에 대한 분석으로 이루어진다.
```

각 항목의 서식:

```markdown
---

## YYYY-MM-DD · 한 줄 요약

**스케치**

> 사용자가 쓴 원문 그대로

**의도**

사용자가 무엇을 원하는지.

**내용**

구체적으로 무엇을 만들거나 바꾸자는 것인지.

**내 생각**

기술적 판단, 대안, 주의할 점, 먼저 정해야 할 것.
```

## 지켜야 할 것

- 스케치는 **기록이지 지시가 아니다.** 메모를 남겼다고 해서 곧바로 구현에 들어가지 않는다.
  사용자가 따로 시키면 그때 만든다.
- 사용자가 "스케치 - ... 그리고 이거 만들어줘"처럼 **명시적으로 실행을 요청하면**
  기록한 뒤 이어서 작업한다.
- 원문은 손대지 않는다. 맞춤법도 고치지 않는다. 분석은 원문 아래에만 쓴다.
- 한 줄 요약은 나중에 훑어볼 때 찾기 쉽도록 구체적으로 짓는다. ("아이디어" 같은 말은 피한다.)
- 이미 있는 스케치와 이어지는 내용이면, **내 생각** 안에서 그 항목을 언급해 연결해 준다.
